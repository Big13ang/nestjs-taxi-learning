Chapter 1, Modules and Providersفصل ۱، Moduleها و Providerها

Dependency injection: ask, and Nest brings itتزریق وابستگی: تو بگو، Nest می‌آورد

How a service gets into your controller, and how one module can use another module's service. The simplest version that is still true.اینکه یک Service چطور به دست Controller تو می‌رسد و یک Module چطور می‌تواند از Service ماژول دیگر استفاده کند. ساده‌ترین نسخه‌ای که هنوز درست است.

Chapter 1, a 10 minute readفصل ۱، ۱۰ دقیقه مطالعه

The one rule of this pageقانون اصلی این صفحه

You never write new. You ask in the constructor, and Nest brings it.تو هیچ‌وقت new نمی‌نویسی. در Constructor می‌خواهی، و Nest آن را می‌آورد.

The idea, in one pictureایده، در یک تصویر

Think of Nest as a front desk. Services are the workers. Your controller does not hire a worker itself — it walks to the front desk and says "I need the drivers worker." The desk already hired that worker this morning (at startup), and sends the same one over.Nest را مثل یک پذیرش (Front Desk) تصور کن. Serviceها کارمندها هستند. Controller تو خودش کارمند استخدام نمی‌کند — می‌رود پیش پذیرش و می‌گوید «کارمند راننده‌ها را می‌خواهم». پذیرش آن کارمند را همان صبح (موقع Startup) استخدام کرده و همان یک نفر را می‌فرستد.

That is all dependency injection is: you declare what you need, someone else builds it and hands it to you. The "someone else" is Nest. Your only job is to ask in the right place: the constructor.تزریق وابستگی (Dependency Injection) فقط همین است: تو اعلام می‌کنی چه می‌خواهی، یک نفر دیگر آن را می‌سازد و به دستت می‌دهد. آن «نفر دیگر» Nest است. تنها کار تو این است که در جای درست بخواهی: در Constructor.

// What you do NOT write anymore:
const service = new DriversService();   // ← you building it yourself

// What you write instead — you only ask:
constructor(private drivers: DriversService) {}
//            ↑ Nest reads this and brings the service in

Using a service in the same module: three movesاستفاده از یک Service در همان Module: سه حرکت

  1. Mark the worker. Put @Injectable() on the service. It tells Nest: "you manage this class, and it may receive things too."کارمند را علامت بزن. روی Service ‏@Injectable() بگذار. به Nest می‌گوید: «مدیریت این Class با توست و خودش هم می‌تواند چیزهایی دریافت کند.»
  2. Register it. List the service in its module's providers. This is the hiring list the front desk works from. Not on the list = the desk has never heard of it.ثبتش کن. Service را در providers ماژولش بنویس. این لیست استخدامی است که پذیرش از رویش کار می‌کند. در لیست نباشد یعنی پذیرش اصلاً اسمش را نشنیده است.
  3. Ask. Write it in the constructor of whoever needs it. Done — Nest injects it when the app starts.بخواه. آن را در Constructor هر کسی که لازمش دارد بنویس. تمام — Nest موقع بالا آمدن برنامه آن را تزریق می‌کند.
// 1 · the service
@Injectable()
export class DriversService {
  findOne(id: number) { return `driver ${id}`; }
}

// 2 · its module — the hiring list
@Module({
  providers: [DriversService],
  exports: [DriversService],   // ← next section explains this line
})
export class DriversModule {}

// 3 · a controller in the SAME module asks
@Controller('drivers')
export class DriversController {
  constructor(private drivers: DriversService) {}

  @Get(':id')
  one(@Param('id') id: string) { return this.drivers.findOne(+id); }
}
One instance for everyoneیک نمونه برای همهBy default Nest builds each service once (a singleton) and hands that same instance to everyone who asks. Ten controllers asking for DriversService all share the one worker — which is why services are the right home for shared state and shared logic.Nest به‌صورت پیش‌فرض هر Service را فقط یک بار می‌سازد (Singleton) و همان یک نمونه را به هر کسی که بخواهد می‌دهد. ده Controller که DriversService می‌خواهند همه از همان یک کارمند استفاده می‌کنند — برای همین Service جای درست State و منطق مشترک است.

Using a service from another module: three more movesاستفاده از Service یک Module دیگر: سه حرکت دیگر

A service is private to its module by default. The trips team cannot just grab the drivers worker — the drivers department has to allow it, and the trips department has to open the door. Picture a module as a department:یک Service به‌صورت پیش‌فرض خصوصیِ Module خودش است. تیم سفرها نمی‌تواند همین‌طوری کارمند راننده‌ها را بردارد — دپارتمان راننده‌ها باید اجازه بدهد و دپارتمان سفرها باید در را باز کند. Module را مثل یک دپارتمان تصور کن:

In the moduleدر ModuleIn the departmentدر دپارتمان
providersthe staff who work hereکارمندهایی که اینجا کار می‌کنند
exportsthe staff allowed to help other departmentsکارمندهایی که اجازه دارند به دپارتمان‌های دیگر کمک کنند
importsthe doors you open to other departmentsدرهایی که به دپارتمان‌های دیگر باز می‌کنی
// DriversModule (already written above) has this line:
//   exports: [DriversService]        ← MOVE 1: drivers allow sharing

// MOVE 2: trips open the door
@Module({
  imports: [DriversModule],
  providers: [TripsService],
  controllers: [TripsController],
})
export class TripsModule {}

// MOVE 3: trips ask, exactly like before
@Injectable()
export class TripsService {
  constructor(private drivers: DriversService) {}

  createTrip(driverId: number) {
    const driver = this.drivers.findOne(driverId);
    return `trip with ${driver}`;
  }
}
Say it as a sentenceبه‌صورت جمله بگو"Drivers export their service, Trips import the Drivers module, and then anyone in Trips can inject it." If you can say that sentence, you can wire any two modules in Nest.«راننده‌ها Service خود را Export می‌کنند، سفرها Module راننده‌ها را Import می‌کنند، و بعد هر کسی در سفرها می‌تواند آن را Inject کند.» اگر این جمله را بتوانی بگویی، هر دو Module در Nest را می‌توانی به هم وصل کنی.

One exception you will meet soon: a module marked @Global() — its exports are available everywhere without importing. Rare on purpose; the config module is the usual case. Do not make your own modules global to save typing.یک استثنا که به‌زودی می‌بینی: ماژولی با @Global() — خروجی‌هایش بدون Import در همه جا در دسترس است. عمداً نادر است؛ Module کانفیگ مورد معمول آن است. برای تنبلی در تایپ کردن، Moduleهای خودت را Global نکن.

The one error you will see, translatedآن یک خطایی که خواهی دید، ترجمه‌شده

Nest can't resolve dependencies of the TripsService (?).
Please make sure that the argument DriversService at index [0]
is available in the TripsModule context.

Plain English: "TripsService asked for DriversService in its constructor, and I could not find it from TripsModule." Run this checklist from the top — it is one of these four, almost every time:به زبان ساده: «TripsService در Constructor خود DriversService را خواست و من نتوانستم آن را از TripsModule پیدا کنم.» این چک‌لیست را از بالا اجرا کن — تقریباً همیشه یکی از همین چهار تاست:

  1. Does the service have @Injectable()?آیا Service ‏@Injectable() دارد؟
  2. Is it in the providers of its module?آیا در providers ماژول خودش هست؟
  3. Is it in that module's exports?آیا در exports آن ماژول هست؟
  4. Did the needing module imports that module?آیا ماژولی که لازمش دارد آن Module را imports کرده است؟

Train on theseبا این‌ها تمرین کن

Drill 1 — what is missing?تمرین ۱ — چه چیزی کم است؟

PaymentsModule lists PaymentsService in its providers but not in its exports. TripsModule imports PaymentsModule, and TripsService asks for PaymentsService in its constructor. What happens, and what is the one-line fix?PaymentsModule ‏PaymentsService را در Providers دارد ولی در Exports ندارد. TripsModule ‏PaymentsModule را Import می‌کند و TripsService در Constructor خود PaymentsService را می‌خواهد. چه اتفاقی می‌افتد و راه‌حل یک‌خطی چیست؟

Answerجواب

Startup fails with "can't resolve dependencies of the TripsService" — importing the module is not enough while the service stays private. Fix: add PaymentsService to exports in PaymentsModule.برنامه با خطای «can't resolve dependencies of the TripsService» بالا نمی‌آید — تا وقتی Service خصوصی بماند، Import کردن Module کافی نیست. راه‌حل: PaymentsService را به exports در PaymentsModule اضافه کن.

Drill 2 — write from memoryتمرین ۲ — از حفظ بنویس

A new FaresService lives in FaresModule. TripsService (in TripsModule) needs it. Write the three changes, from memory, in order.یک FaresService جدید در FaresModule زندگی می‌کند. TripsService (در TripsModule) به آن نیاز دارد. هر سه تغییر را از حفظ و به ترتیب بنویس.

Answerجواب

1) FaresModule: add FaresService to exports. 2) TripsModule: add FaresModule to imports. 3) TripsService: constructor(private fares: FaresService) {}.۱) در FaresModule: ‏FaresService را به exports اضافه کن. ۲) در TripsModule: ‏FaresModule را به imports اضافه کن. ۳) در TripsService: بنویس constructor(private fares: FaresService) {}.
