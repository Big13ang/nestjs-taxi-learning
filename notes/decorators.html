Decorators: code that runs when a class is definedDecoratorها: کدی که هنگام تعریف Class اجرا می‌شود

A decorator is just a function that receives the thing it sits on — a class, a method, a property, or a parameter — and can observe it, change it, or leave metadata on it. It runs once, at definition time, not when you use the thing.Decorator در اصل فقط یک Function است که چیزی را که رویش نشسته دریافت می‌کند — یک Class، یک Method، یک Property یا یک Parameter — و می‌تواند آن را ببیند، تغییرش بدهد یا رویش Metadata بگذارد. فقط یک بار، در زمان تعریف (Definition Time) اجرا می‌شود، نه وقتی از آن چیز استفاده می‌کنی.

Chapter 1, TypeScript and Nest, a 12 minute readفصل ۱، TypeScript و Nest، ۱۲ دقیقه مطالعه

The one rule of this pageقانون اصلی این صفحه

A decorator runs once, when the class definition is evaluated. Not on new, not per request.Decorator فقط یک بار اجرا می‌شود، وقتی تعریف Class ارزیابی می‌شود. نه با new، نه برای هر Request.

Two small fixes to the raw note: it's class Feed {} — no () after the name — and "runs when you start your project" is true because that's when the file is first imported and the class definition is evaluated. The precise rule is:دو اصلاح کوچک در یادداشت خام: شکل درست class Feed {} است — بعد از اسم Class پرانتز نمی‌آید — و «وقتی پروژه را اجرا می‌کنی اجرا می‌شود» از این جهت درست است که در همان لحظه فایل برای اولین بار Import می‌شود و تعریف Class ارزیابی (Evaluate) می‌شود. قانون دقیق این است:

In Nest, "definition time" means module load — app startup. That is the moment the rule above refers to.در Nest «زمان تعریف» یعنی زمان Load شدن Module — همان بالا آمدن برنامه. قانون بالا دقیقاً به همین لحظه اشاره می‌کند.

The split that explains Nestتفکیکی که Nest را توضیح می‌دهدThe decorator function runs at definition time. What it leaves behind is what acts later: most Nest decorators only store metadata (Reflect.defineMetadata) — e.g. @Get(':id') writes "this method = GET /:id". Nest reads that metadata at startup and at runtime. Definition-time execution, runtime effect.خودِ Function دکوراتور در زمان تعریف اجرا می‌شود. چیزی که از خودش به جا می‌گذارد بعداً عمل می‌کند: بیشتر Decoratorهای Nest فقط Metadata ذخیره می‌کنند (Reflect.defineMetadata) — مثلاً @Get(':id') می‌نویسد «این Method یعنی GET /:id». Nest این Metadata را هنگام Startup و Runtime می‌خواند. اجرا در زمان تعریف، اثر در زمان اجرا.

Mental modelمدل ذهنی

Think of a decorator as a sticker you put on a blueprint, not on the houses built from it. You sticker the blueprint once, while drawing it. Every house built later carries the sticker's effect — but you never re-sticker per house. Heavy work (DB calls, network) does not belong in a decorator for exactly this reason: it would run once, at load, before your app is ready.Decorator را مثل برچسبی روی نقشه ساختمان تصور کن، نه روی خانه‌هایی که از آن نقشه ساخته می‌شوند. برچسب را یک بار، موقع کشیدن نقشه می‌زنی. هر خانه‌ای که بعداً ساخته شود اثر برچسب را دارد — ولی برای هر خانه دوباره برچسب نمی‌زنی. کار سنگین (تماس با DB، شبکه) دقیقاً به همین دلیل جایگاهی در Decorator ندارد: یک بار، موقع Load اجرا می‌شود، قبل از اینکه برنامه‌ات آماده باشد.

All possible decorators — there are exactly 5 kindsهمه Decoratorهای ممکن — دقیقاً ۵ نوع وجود دارد

Every decorator in TypeScript (and therefore in Nest) is one of these five. What changes is what it can sit on and what arguments it receives.هر Decorator در TypeScript (و در نتیجه در Nest) یکی از همین پنج نوع است. چیزی که عوض می‌شود این است که روی چه چیزی می‌نشیند و چه Argumentهایی دریافت می‌کند.

Scaffold ‏Nest CLI هر دو را از قبل تنظیم کرده است.

Decorator factory — a decorator that takes argumentsFactory Decorator — دکوراتوری که Argument می‌گیرد

A plain decorator is the function. A factory is a function that returns that function — that's the only way to pass your own values in.دکوراتور ساده خودش همان Function است. Factory تابعی است که آن Function را برمی‌گرداند — و این تنها راه پاس دادن مقدارهای خودت است.

function Logger(prefix: string) {        // 1 · FACTORY — takes YOUR arguments
  return function (target: Function) {   // 2 · the actual DECORATOR
    console.log(`[${prefix}] ${target.name} was defined`);
  };
}

@Logger('FEED')   // call the factory → it returns a decorator → decorator runs on the class
class FeedService {}

// App starts, file is imported → console: [FEED] FeedService was defined
// new FeedService() ten times  → nothing. It already ran, once.
Watch out — the parentheses are the whole differenceحواست باشد — همه تفاوت در پرانتزهاست@Logger = the function itself is the decorator (no arguments possible). @Logger('FEED') = call the factory first, use what it returns. Nearly every Nest decorator is a factory: @Controller('feed'), @Get(':id'), and your future @Roles('ADMIN') in the taxi project is just SetMetadata('roles', ...roles) — a factory.@Logger یعنی خود Function همان Decorator است (امکان پاس دادن Argument نیست). @Logger('FEED') یعنی اول Factory صدا زده می‌شود و خروجی‌اش استفاده می‌شود. تقریباً همه Decoratorهای Nest از نوع Factory هستند: @Controller('feed')، @Get(':id') و @Roles('ADMIN') که در پروژه تاکسی خواهی ساخت فقط SetMetadata('roles', ...roles) است — یک Factory.

Multiple decorators — why the order looks reversedچند Decorator — چرا ترتیب برعکس به نظر می‌رسد

@First()
@Second()
@Third()
class Demo {}

Two different phases, two different directions:دو فاز متفاوت، دو جهت متفاوت:

PhaseفازOrderترتیبFor the exampleدر این مثال
1. Factories are evaluated۱. Factoryها ارزیابی می‌شوندTop → bottomاز بالا به پایینFirst() → Second() → Third()
2. Decorators are invoked۲. Decoratorها اجرا می‌شوندBottom → topاز پایین به بالاThird → Second → First

Why? It's function composition. @f @g x means f(g(x)) — the decorator closest to the class has to finish first, so the next one up receives its result and can wrap it. Exactly like an onion, or a stack: the last one you put on is the first one that actually applies.چرا؟ چون ترکیب تابع (Function Composition) است. @f @g x یعنی f(g(x)) — دکوراتوری که به Class نزدیک‌تر است باید زودتر تمام شود تا دکوراتور بالایی نتیجه‌اش را بگیرد و دور آن بپیچد. دقیقاً مثل پیاز یا Stack: آخرین چیزی که می‌گذاری، اولین چیزی است که اعمال می‌شود.

Memory lineجمله حافظهFactories read top-down. Decorators run bottom-up. Closest to the class runs first.Factoryها از بالا به پایین خوانده می‌شوند. Decoratorها از پایین به بالا اجرا می‌شوند. نزدیک‌ترین به Class زودتر اجرا می‌شود.

And inside one whole class, TypeScript applies things in this fixed order:و داخل یک Class کامل، TypeScript همه چیز را با این ترتیب ثابت اعمال می‌کند:

  1. Parameter, then method / accessor / property decorators — for each instance memberاول Parameter و بعد Method / Accessor / Property — برای هر عضو Instance
  2. Same — for each static memberهمان ترتیب — برای هر عضو Static
  3. Parameter decorators — for the constructorParameter Decoratorها — برای Constructor
  4. Class decorators — lastClass Decoratorها — در آخر

Examples to memorize — one per kindمثال‌هایی برای حفظ کردن — برای هر نوع یکی

Don't memorize all five perfectly today. Memorize example 1 (class + factory) cold, and be able to recognize the shape of the other four.لازم نیست امروز هر پنج تا را کامل حفظ کنی. مثال ۱ (Class + Factory) را کاملاً حفظ کن و شکل چهار تای دیگر را بتوانی تشخیص بدهی.

1 · Class decorator (factory) — tag a class۱ · Class Decorator از نوع Factory — برچسب زدن به Class

function Tag(label: string) {
  return function (target: Function) {
    (target as any).label = label;   // leave something on the class itself
  };
}

@Tag('feed-service')
class FeedService {}

console.log((FeedService as any).label);  // 'feed-service' — set at definition time

2 · Method decorator — wrap a method (timing)۲ · Method Decorator — پیچیدن دور Method (زمان‌سنجی)

function LogTime(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = async function (...args: any[]) {
    const start = Date.now();
    const result = await original.apply(this, args);
    console.log(`${key} took ${Date.now() - start}ms`);
    return result;
  };
  return descriptor;   // method/accessor decorators may return a new descriptor
}

class FeedService {
  @LogTime
  async getFeed() { /* ... */ }   // decorator runs at definition; the WRAPPER runs per call
}
See the split againتفکیک را دوباره ببین

@LogTime itself ran once, at startup, and swapped in a wrapper. The wrapper is what runs on every getFeed() call. That two-step — decorate once, effect per use — is how almost all powerful decorators work.خود @LogTime یک بار، موقع Startup اجرا شد و یک Wrapper جایگزین کرد. این Wrapper است که با هر بار صدا زدن getFeed() اجرا می‌شود. همین دو قدم — یک بار Decorate کن، در هر استفاده اثر بگذار — روش کار تقریباً همه دکوراتورهای قدرتمند است.

3 · Property decorator — metadata only۳ · Property Decorator — فقط Metadata

function Required(target: any, key: string) {
  const fields: string[] = Reflect.getMetadata('required', target) ?? [];
  Reflect.defineMetadata('required', [...fields, key], target);
}

class CreateTripDto {
  @Required
  pickup!: string;   // no descriptor exists for properties — metadata is all you get
}

4 · Parameter decorator — mark an argument۴ · Parameter Decorator — علامت زدن یک Argument

function LogParam(target: any, key: string | undefined, index: number) {
  console.log(`Parameter #${index} of ${String(key ?? 'constructor')} is decorated`);
}

class TripsController {
  create(@LogParam dto: object) {}   // prints at definition time: Parameter #0 of create…
}

This is the family Nest's createParamDecorator() builds on — your @CurrentUser() in the taxi project will be one of these, except Nest gives it a factory that also runs per request to extract the value.این همان خانواده‌ای است که createParamDecorator() در Nest رویش ساخته شده — @CurrentUser() تو در پروژه تاکسی یکی از همین‌ها خواهد بود، با این تفاوت که Nest به آن یک Factory می‌دهد که برای هر Request هم اجرا می‌شود تا مقدار را استخراج کند.

5 · Accessor decorator — guard a setter۵ · Accessor Decorator — محافظت از Setter

function Positive(target: any, key: string, descriptor: PropertyDescriptor) {
  const originalSet = descriptor.set!;
  descriptor.set = function (value: number) {
    if (value < 0) throw new Error(`${key} cannot be negative`);
    originalSet.call(this, value);
  };
}

class Wallet {
  @Positive
  set balance(value: number) { /* store it */ }
}

Drill 2 — spot the bugتمرین ۲ — باگ را پیدا کن

A teammate writes a decorator that opens a database connection inside the decorator function "so it's ready before any request." What's wrong?یکی از هم‌تیمی‌ها دکوراتوری می‌نویسد که داخل خود تابع دکوراتور یک Connection به دیتابیس باز می‌کند «تا قبل از هر Request آماده باشد». مشکلش چیست؟

Answerجواب

The decorator runs at class-definition / module-load time — before Nest has built the app, read config, or connected its own providers. Decorators should be cheap: store metadata or wrap a method. Real connections belong in a provider's lifecycle hook (e.g. onModuleInit — Chapter 2).دکوراتور در زمان تعریف Class / Load شدن Module اجرا می‌شود — قبل از اینکه Nest برنامه را بسازد، Config را بخواند یا Providerهای خودش وصل شوند. دکوراتور باید سبک باشد: Metadata ذخیره کن یا یک Method را Wrap کن. Connectionهای واقعی جای‌شان در Lifecycle Hook یک Provider است (مثلاً onModuleInit — فصل ۲).
